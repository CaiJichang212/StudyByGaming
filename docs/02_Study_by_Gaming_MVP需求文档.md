# Study by Gaming MVP 需求文档

生成日期：2026-07-04  
版本：MVP v0.1，适用于 3 小时线下黑客松  
示例文档：《CANN 社区版 8.5.0 Ascend C 算子开发指南》

---

## 1. 产品定位

Study by Gaming 是一个把技术 PDF 文档转换为游戏化学习路径的 Web 应用。MVP 版本聚焦 Ascend C 算子开发指南的入门章节，把“什么是 Ascend C、环境准备、HelloWorld、Add 自定义算子开发、核心 API”制作成 5 个闯关任务。

一句话 Demo：

> 上传/选择一本技术 PDF，系统生成一张学习地图；用户像打游戏一样通过关卡，系统记录进度、错题、提示次数和薄弱知识点。

---

## 2. MVP 目标与非目标

### 2.1 MVP 目标

3 小时内必须跑通以下闭环：

1. 展示一张 Ascend C 新手村学习地图。
2. 用户可以进入关卡，完成选择题、配对题、排序题、代码填空题中的至少 3 种。
3. 每次答题都有即时反馈、XP 奖励、错误解释和提示。
4. 系统能记录学习历史：已完成关卡、答题结果、错误知识点、提示次数、耗时。
5. 系统能展示学习仪表盘：总 XP、完成度、薄弱点、推荐复习任务。
6. Demo 能说明未来如何接入任意 PDF 和 RAG 生成。

### 2.2 MVP 非目标

以下内容不要放入 3 小时 MVP：

- 不做完整 2517 页 PDF 自动解析。
- 不做真实 Ascend C 编译运行环境。
- 不做多人账号、排行榜、社交系统。
- 不做完整 xAPI/LRS 标准接入。
- 不做高性能 RAG、复杂向量检索、跨文档问答。
- 不做移动端适配和复杂动画。

## 3. 目标用户

### 3.1 核心用户

- 计算机/C++ 基础较好，但刚接触 Ascend C 的开发者。
- 企业内部需要快速学习硬件/SDK/算子开发文档的新员工。
- 黑客松/训练营中需要快速掌握长文档核心路径的学习者。

### 3.2 用户痛点

| 痛点 | 表现 | MVP 解决方式 |
|---|---|---|
| 文档太长 | 2517 页，看不出先学什么 | 生成 5 关新手村地图 |
| 术语多 | TPipe、TQue、Tiling、Global Memory 等抽象 | 卡牌解释 + 配对题 |
| 流程复杂 | 环境、核函数、编译、运行、验证 | 流程排序题 |
| 不知道自己哪里不会 | 看完但不会开发 | 记录错题和难点标签 |
| 学习缺乏反馈 | 阅读没有成就感 | XP、通关、Boss 战 |

## 4. MVP 用户故事

### 4.1 学习者视角

1. 作为学习者，我希望打开网页就看到“Ascend C 新手村地图”，知道学习路线。
2. 作为学习者，我希望每一关只学一个小目标，避免被长文档淹没。
3. 作为学习者，我希望答错后看到“大白话解释”和“回到原文”的提示。
4. 作为学习者，我希望系统记录我错在哪些知识点，方便复习。
5. 作为学习者，我希望最终通过 Boss 战，确认自己理解 Add 算子开发流程。

### 4.2 演示者/评委视角

1. 作为评委，我希望 30 秒内看懂这个产品解决了什么问题。
2. 作为评委，我希望看到它不是普通 quiz，而是有学习路径、游戏化反馈和数据闭环。
3. 作为评委，我希望看到它未来可以扩展到任意 PDF 技术文档。

## 6. MVP 关卡设计

### 关卡 0：新手村入口 - 这本 2517 页文档到底讲什么？

目标：让用户理解 Ascend C 文档结构。  
题型：章节匹配题。  
知识点标签：`doc_structure`、`learning_path`。

示例任务：

> 把以下章节和功能配对：入门教程、编程指南、算子实践参考、API 参考。

通关标准：答对 3/4。

---

### 关卡 1：认识 Ascend C

目标：理解 Ascend C 是 CANN 面向算子开发的编程语言，原生支持 C/C++ 标准规范，并提供基础 API、高阶 API、算子模板库、Python 前端等能力。  
题型：选择题 + 卡牌翻转。  
知识点标签：`ascend_c_intro`、`api_layers`。

示例题：

> Ascend C 的主要用途是什么？
>
> A. 写普通 Web 后端  
> B. 面向昇腾 AI 处理器开发高性能自定义算子  
> C. 替代 Python 做数据分析  
> D. 管理 Linux 进程

正确答案：B。

---

### 关卡 2：环境准备装备栏

目标：理解开发前需要 CANN 软件包、环境变量、CMake 版本等准备。  
题型：勾选题。  
知识点标签：`environment`、`cann`、`cmake`。

示例题：

> 开发 Ascend C 算子前，哪些准备通常是必要的？
>
> - 安装 CANN 软件包
> - 执行 `source ${install_path}/set_env.sh`
> - 安装满足要求的 CMake
> - 安装 Photoshop

通关标准：选对全部必要项，不能选 Photoshop。

---

### 关卡 3：HelloWorld 洞穴

目标：理解核函数、Host 初始化、stream、`<<<>>>` 调用和同步。  
题型：流程排序题。  
知识点标签：`kernel_launch`、`acl_runtime`、`stream`。

示例排序：

1. `aclInit(nullptr)`
2. `aclrtSetDevice(deviceId)`
3. `aclrtCreateStream(&stream)`
4. `hello_world<<<blockDim, nullptr, stream>>>()`
5. `aclrtSynchronizeStream(stream)`
6. 释放资源

通关标准：顺序完全正确。

---

### 关卡 4：Add 算子地下城

目标：理解 Add 自定义算子的开发流程：算子分析 -> Kernel 实现 -> 运行验证。  
题型：API 配对 + 流程排序。  
知识点标签：`add_custom`、`datacopy`、`vector_add`、`queue`。

示例配对：

| API/机制 | 作用 |
|---|---|
| DataCopy | Global Memory 与 Local Memory 之间搬运数据 |
| Add | 完成矢量加法计算 |
| AllocTensor / FreeTensor | 申请和释放 Tensor |
| EnQue / DeQue | Queue 队列管理与同步 |

通关标准：配对正确率 ≥ 80%。

---

### 关卡 5：Boss 战 - 你能描述一个 Add 算子吗？

目标：综合验证用户是否真正理解 Add 自定义算子开发。  
题型：混合题，包含规格选择、流程排序、代码填空。  
知识点标签：`boss_add_operator`。

Boss 战任务：

1. 选择 Add 算子的输入输出：x、y、z。
2. 选择 Shape 和数据类型：`(8, 2048)`、`float`、`ND`。
3. 排序单核流水线：CopyIn -> Compute -> CopyOut。
4. 选择 Add 实现所需接口：DataCopy、Add、AllocTensor、FreeTensor、EnQue、DeQue。
5. 填空核函数限定符：`__global__ __aicore__ void add_custom(...)`。

通关标准：总分 ≥ 80，奖励徽章“Add 算子见习开发者”。

## 7. 核心功能需求

### 7.1 P0 必做功能

| 编号 | 功能 | 描述 | 验收标准 |
|---|---|---|---|
| P0-1 | 首页学习地图 | 展示 5 个关卡、锁定/已完成状态 | 能点击进入未完成关卡 |
| P0-2 | 关卡知识卡 | 每关展示 1-3 张简短知识卡 | 每张不超过 120 字 |

| P0-7 | Boss 战 | 综合题，通关后给徽章 | 能完成并展示通关结果 |

| P2-3 | 多用户账号 | 记录长期学习历史 |

## 8. 学习数据需求

MVP 最重要的数据不是用户注册信息，而是学习行为。

### 8.1 事件模型

建议统一记录为 `LearningEvent`：

```json
{
  "id": "evt_001",
  "userId": "demo_user",
  "sessionId": "session_001",
  "eventType": "challenge_submitted",
  "questId": "quest_add_01",
  "challengeId": "challenge_api_match",
  "result": "wrong",
  "score": 60,
  "tags": ["datacopy", "queue"],
  "usedHint": true,
  "timeSpentSec": 42,
  "createdAt": "2026-07-04T14:00:00+08:00"
}
```

### 8.2 需要统计的指标

| 指标 | 计算方式 | 用途 |
|---|---|---|
| 完成度 | 已完成关卡 / 总关卡 | 展示进度 |
| XP | 答对、通关、复习累计 | 游戏反馈 |
| 正确率 | 正确提交 / 总提交 | 掌握度 |
| 平均耗时 | 关卡耗时均值 | 判断难度 |
| 提示次数 | `hint_requested` 次数 | 识别卡点 |
| 薄弱标签 | 错题 + 提示最多的 tags | 推荐复习 |
| Boss 分数 | Boss 战综合分 | 通关判断 |

## 10. 3 小时黑客松执行计划

### 第 0-20 分钟：搭项目和定内容

- 使用 Next.js + Tailwind 初始化项目。
- 写死 `quests.json`，包含 5 个关卡、知识卡、题目、答案、标签。
- 明确 Demo 话术：从“2517 页 PDF”到“5 个关卡”。

产出：项目可启动，内容数据准备好。

### 第 20-60 分钟：完成核心 UI

- 首页学习地图。
- 关卡页。
- 题目组件：选择题、配对题、排序题。
- XP/进度显示。

产出：用户能从首页进入关卡并答题。

### 第 60-100 分钟：完成学习记录

- localStorage 或 SQLite 记录 events。
- 记录 challenge_submitted、quest_completed、hint_requested。
- 计算 progress、XP、weak tags。

产出：刷新后数据不丢，仪表盘有统计。

### 第 100-140 分钟：Boss 战和反馈体验

- 添加 Boss 战混合题。
- 答对/答错反馈。
- 通关徽章。
- 提示按钮。

产出：完整学习闭环。

### 第 140-170 分钟：打磨 Demo

- 优化首页文案。
- 增加“上传 PDF 生成游戏”的假入口/未来入口。
- 增加“原文来源：Ascend C 文档章节”的展示。
- 准备演示数据。

产出：评委能快速看懂产品价值。

### 第 170-180 分钟：演示排练

演示脚本：

1. 展示 PDF 很长，学习门槛高。
2. 打开 Study by Gaming，看到学习地图。
3. 进入 Add 地下城，完成 API 配对题。
4. 故意答错一次，展示提示和难点记录。
5. 通过 Boss 战，获得徽章。
6. 打开仪表盘，展示用户学习历史和薄弱点。
7. 说明后续接入 PDF 自动解析 + RAG + xAPI。

## 11. 验收标准

MVP 完成标准：

- 用户能完成至少 3 个关卡。
- 至少有 3 种互动题型。
- 用户答题后能看到正确/错误反馈。
- 系统能记录学习事件。
- 仪表盘能展示进度、XP、薄弱点。
- Boss 战能通关并发徽章。
- Demo 话术能说明未来可扩展到任意技术 PDF。

失败标准：

- 只有静态页面，没有答题交互。
- 只有 quiz，没有学习记录。
- 只有聊天机器人，没有关卡路径。
- 过度依赖实时 LLM，导致演示不稳定。

---

## 12. MVP 成功判断

黑客松中，Study by Gaming 的成功不在于“自动生成多少题”，而在于让评委看到这个闭环：

```text
长技术文档 -> 知识地图 -> 互动关卡 -> 即时反馈 -> 学习数据 -> 个性化复习
```

只要这个闭环成立，MVP 就成立。
